# 普算 · 合并包 v2.0.0

**一个插件装齐普算的全部功能。** 对应普算 **0.3.3**，适配 DSH **0.1.7-rc.2 与 0.2.0-rc.2**。

> ⚠ 这一版把原来的三个包（`pusuan-knowledge` / `pusuan-persona` / `pusuan-divination`）
> **合并成了一个**。那三个**不要再装**，否则技能、语料、预设会重复。

---

## 下载哪个

**只有一个**：

| 文件 | 作用 | 大小 |
|---|---|---|
| `pusuan.zip` | 全套：8 技能 + 570 篇语料与检索 + 5 个人格预设 + 四个起卦器与量化/记录 | 13.8 MB |

**装法**：解压后把 `pusuan` 目录装进 DSH（界面里「添加插件」选它，或
`dsh plugin --profile web add <路径>/pusuan`），然后**重启引擎**。

## 本版新东西

### ① 合并成一个包

原来要装三个，现在装一个。旧的知识库/占卜/人格三个包都**不管技能**，
技能本来单独在 `pusuan-skills` 里、没进交付；现在一并带上了。

合并后四处投影（技能、语料、内核包、历法依赖）共用**一个版本戳**
（插件版本 + 每个随包版本）。这顺手修掉了一个旧地雷：老的知识库包是
「目标存在就跳过」，升级后旧文件永久留存、**修复不生效且没有任何报错**。

### ② 「军师 / 人话 / 温柔」三个人设

普算 0.3.3 的这三个人设在原版里属于「对话人设」（靠设置页选择），
而那个设置页依赖的 API 在两代内核上都没有。本包换了落地方式：
**做成预设**，与「普算·标准 / 提问模式」同一套机制。

人设文本按上游的拼装规则生成：`普算本体正文 + 人设框架 + 风格正文`，
三段**逐字取自上游**；上游那句优先级声明原样保留在最前面
（「人设只支配语气、表达与互动风格，不改变任何规则与占卜流程；与规则冲突时，一律以规则为准」）。

> 差别只在入口：原版在设置页里逐对话选、选定不可改；本包靠**切预设**生效。
> 效果一样。

### ③ 修了「六壬编造年龄」

`liuren_paipan` 不传年龄时，上游会**照样**推出一份行年与本命，格式合法、无标记、无警告 ——
模型分不出真假，而六壬行年直接决定「凶应落在谁身上、从何时起」。

实测（同一时刻、同一性别，只改 age）：

| 调用 | 虚岁 | 本命 | 行年 |
|---|---|---|---|
| 只给 `sex:"女"` | 19 | 戊子 | **甲寅** ← 编造 |
| `sex:"女", age:14` | 15 | 壬辰 | **戊午** ← 真实 |

对照两次盘面的**全部 50 个顶层字段**：只有 `xx_xn` / `xx_bm` / `xx_xs` 三个随年龄变，
其余 47 个逐字相同 —— 伪造的干支被插进了一份其它方面完全正常的盘面里。

**本版处理**：不给年龄/性别填默认值；在工具出口把引擎凭空推出来的那三个字段剔掉，
并留一条说明。**没给年龄时不再有任何行年**，需要行年就先去问用户。

> 这是**上游原始缺陷**：普算 0.3.3 与 0.3.0 的这个包字节级一致，至今未修；
> 已同步修的还有更早的「不传问事时间就必崩」。

### ④ 同步到普算 0.3.3

随包全部升到 0.3.3；新增两个工具 `quantify_records`（量化记录）与
`divination_records`（占卜记录）；标准模式提示词的两处改动也跟上了。

## 验证

同一套脚本在两代内核上各跑一遍（真 pnpm 安装 + 真内核启动 + 真调 `execute()`）：

| 检查 | 0.1.7-rc.2 | 0.2.0-rc.2 |
|---|---|---|
| 8 个技能投影到 `<dshHome>/skills/` 且 frontmatter 合法 | ✅ | ✅ |
| 5 个新预设齐全 + 内核原版 4 个未动 + 默认仍是 `standard` | ✅ | ✅ |
| 军师预设三截齐全（本体 + 框架 + 风格正文） | ✅ | ✅ |
| 8 个工具全注册 | ✅ | ✅ |
| 语料 1 库 / 566 片 | ✅ | ✅ |
| 四个起卦器真调 `execute()` 成功 | ✅ | ✅ |
| 六壬不再编造年龄 | ✅ | ✅ |
| 启动告警 | **0** | **0** |

另有升级复用测试：同版本跳过、升版本干净重投，均按设计工作。

**未验证**：`divination_quantify` 的**量化质量** —— 它要跑四次模型阶段，
且需要先占一卦、拿到事后反馈才用得上。装机与注册本身没问题。

## 已知问题（上游遗留）

- **`quantify_record_delete` 不可用**：普算 0.3.1 的发行说明写了它，但上游 0.3.3 的构建产物
  从未把它接上（没被 import、也没进 `exports`）。本包不替上游发明挂载逻辑。
- **`divination-methods` 没挂载**：它依赖的 API 两代内核都没有。损失很小 ——
  只是技能目录里「哪个版本是默认」的标记与设置页开关。
